# 04 "时序全部收敛"的假象：约束没有生效

中文 | [English](04_timing_constraints_not_applied_en.md)

会话：相机 + QCNN + DP 叠加层合并工程的 Vivado 构建　日期：2026-11-01～02

## 提示词（整理）
> 三层（消息、推理、屏幕输出）要相互配合、时序收敛。先写代码、仿真、构建，暂时不要烧录。

## 模型回答（摘要）
- 每次构建后不只看 WNS，还检查时钟列表、CDC 报告，并和已知可用的工程对比。
- 新写 RTL 先在 Verilator 与 Vivado xsim 两个仿真器里和 Python 参考模型逐位对比（推理 144/144，叠加层一帧 921,600 像素全部一致）。

## 纠错
模型在三次"看起来通过"的构建里各发现一处约束没生效：
1. 第一次构建 100 MHz 域 WNS +3.6 ns，但时钟列表里只有 `clk_pl_0`，74.25 MHz 视频时钟没被检查，原因是约束文件没被应用。模型按真实层次改写为顶层 XDC，在布线后的 checkpoint 里试过再重建。
2. 合并相机设计后，相机字节时钟没出现在时钟表里。模型拿板上正在用的纯相机工程对比，补齐约束后再看报告。
3. 屏幕取帧的 CDC 约束用了 `foreach`，XDC 不支持，约束整段没生效。模型展开成逐条约束后重建。
- 重启构建时 `pkill -f` 的模式匹配到了 SSH 会话自己的命令行，把连接杀掉。模型改为按 PID 停止旧构建。

## 结果
| 构建 | 时钟 | 余量 |
|---|---|---|
| 推理 + 叠加层（修约束后） | 100 MHz / 74.25 MHz 视频 | +4.09 ns / +10.48 ns |
| 相机 + 推理 + 显示合并 | 100 MHz / 相机字节时钟 / DP 像素时钟 | +3.98 / +5.88 / +8.41 ns |

- 合并工程资源：逻辑 22%、DSP 31%、块 RAM 21%。CDC 报告里剩下的 Critical 全部在相机原有 D-PHY 部分。
- 经验写进流程：WNS 为正之前，先确认每个时钟都在时钟表里、每条例外约束确实被应用。
