# 05 RTL 仿真通过、综合后权重全为 0

会话：QCNN 推理核前期验证（单帧形状，XC7Z020）　日期：2026-09-16（据当日结果记录 `results_2026-09-16`）

## 提示词（整理）
> （据当时记录重述）推理核 RTL 仿真和参考模型逐位一致，但综合后网表仿真输出不对，像是权重全为 0。时序和资源报告都正常。
> 权重 ROM 是在 `initial` 块里用循环按 lane 切片的。找出原因。

## 模型回答（摘要）
- Vivado 综合只处理 `initial` 块里的常量赋值和 `$readmemh`；循环里按参数算下标填存储器属于非常量初始化，综合会丢弃，ROM 变成全 0。RTL 仿真器会执行 `initial`，所以 RTL 仿真看不出来。
- 时序和资源报告都不会因为 ROM 内容是 0 而报警，只能靠网表仿真发现。

## 纠错
- 权重切片的 `initial` 写法出自助手自己写的 RTL。问题在综合后网表仿真时暴露。
- 修复：由 Python 参考模型直接按 lane 导出 `.mem` 文件，RTL 只用 `$readmemh` 读文件，存储器内容与硬件结构分开。
- 同一阶段还发现另外两处同类问题，一并记录：偏置 ROM 按 8 位计数器推成 8192 深、BRAM 一度 139/140；门级仿真前 100 ns 的 GSR 复位会吞掉提前送入的数据。

## 结果
- 综合后功能仿真固定进流程：`sim/rtl/run_postsynth.sh`、`run_xsim_layer.sh`、`run_xsim_head.sh`。
- 参考模型（`src/model/qcnn_int.py`）成为权重、移位参数和测试向量的唯一来源，换模型不改 RTL；当前训练权重下 144/144 逐位一致。
- 三条经验整理为技能包第 1、2 项。
