# 08 PL 接管 Mini DP 后黑屏：live 输入的同步极性

中文 | [English](08_dp_live_sync_polarity_en.md)

会话：PL 合成的 800×480 界面经 ZynqMP DP 控制器 live 输入输出到 7 寸屏　日期：2026-11-02

## 提示词（整理）
> 先解决屏识别。（之后）有彩条。800×480 正常。（PL 接管后）黑屏。

## 模型回答（摘要）
- 先只读诊断：HPD=1 但 AUX 通道每次超时、EDID 0 字节，判断是转接头问题（ZynqMP DP 不支持 DP++，无源转接头会是这种表现）。用户换线后 EDID 读到 128 字节，型号字段 CH7218（有源 DP→HDMI 芯片），只报 1920×1080。
- 用 `drm_mode_test.py` 临时切 800×480@60（像素时钟 33.26 MHz，10 分钟后自动恢复），画 1 像素细线测试图，确认屏没有二次缩放。主平面不接受 XRGB8888，改用 RGB565。
- 切到 PL live 输入后：PL 每秒稳定出 60 帧，DP 控制器也切到了 PL 的时钟和时序，但屏上黑。

## 纠错
- 第一次黑屏时模型看到背景读取、相机读取计数都是 0，怀疑 PL 到内存的读通道不通。随后发现当时只开了测试彩条（CTRL=0x2），按设计彩条模式本来就不读内存，这个"故障"是误判。打开正式界面后背景每帧取 480 行、相机每帧取 240 行，读通道正常，问题范围缩到 PL 输出之后。
- 新嫌疑是同步极性：800×480 模式的同步低有效，PL 照此输出。查 Xilinx 驱动源码，切 live 时不改同步极性，文档也没写 live 输入要求哪种极性，只能实测。
- 模型做了一个 20 s 自动回退的测试：PL 输出改高有效同步、只出彩条。用户回报"看到彩条"。
- 同一会话还发现：用户的采集网页预览变黑与烧录无关，是断电后相机曝光回到默认 1 行（RAW 均值约 17），网页上的"自动曝光"勾选框显示的是页面默认值，不是板子实际状态。

## 结果
- 结论：DP 控制器 live 输入只认高有效同步。`dp_live.py` 改为固定输出高有效同步，屏侧极性仍由 DP 控制器按模式处理。
- 正式界面读回：60 帧/s，背景约 28,800 行/s，相机约 14,400 行/s，无超时。
- 触摸屏同时打通：`wch.cn USB2IIC_CTP_CONTROL`，坐标 0–4096，四角校准误差 20 像素以内，写入 `ui_layout.py`。
