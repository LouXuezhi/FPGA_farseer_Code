# 06 合并比特流上板：AXI 位宽与复位极性两处仿真测不出的错误

会话：在 Linux 运行时通过 FPGA manager 加载合并比特流　日期：2026-11-02

## 提示词（整理）
> 可以，烧录。（板子刚断过电）先重新拉起相机服务，确认没问题再烧录。

## 模型回答（摘要）
- 烧录前确认相机服务：芯片 ID 0x9281，145 fps，相隔 1 秒两次取帧帧号前进 146，确认取到的是新帧。
- 先备份原相机比特流到 `/root/cam/backup_20261102/`，再加载合并版。
- 加载后相机服务报"比特流版本 0x00000000"。模型逐个读各模块寄存器，发现 32 位字里低 8 位以外的内容全读成 0。
- 原因：板子开机时 PS 已把 PS-PL 的 AXI 口配成 32 位（寄存器口）和 64 位（内存口），运行时加载比特流不会改它；合并工程用了 Vivado 默认的 128 位。仿真不经过 PS，所以没测出来。
- 先回退原相机比特流（145 fps、800 行、芯片 ID 正确），改位宽重建后再烧。

## 纠错
- 第二次烧录后相机正常（版本 0xCA928103），但 PL 推理的 DMA 卡住，MM2S 状态 halted。
- 模型先在主机侧的假 DMA 测试里补上"共享复位"的模型，确认这类测试本来能抓到问题；再查连线，发现 `temp_link/rst` 是高有效，却接到了低有效的 `peripheral_aresetn`，推理核一直处于复位，DMA 因此挂住。
- 改接 `peripheral_reset` 后重建，时序仍收敛。
- 另一个 bug：VDMA 帧存数量寄存器在这一版读出 0，`dp_live.py` 改为按已设置的起始地址数帧存，相应测试同步修改。

## 结果
- 合并比特流上板后：相机 144.8 fps，每帧 800 行，坏包头 0，FIFO 溢出 0；Mac 端 3 s 收到 434 帧，帧号连续。
- PL 推理真正跑起来：4 组图像对、每组 9 路输出，共 2.94 ms。
- 相机寄存器地址（0xA0000000、0xA0010000）不变，采集脚本无需修改；推理 DMA 在 0xA0020000，显示模块在 0xA0030000。
