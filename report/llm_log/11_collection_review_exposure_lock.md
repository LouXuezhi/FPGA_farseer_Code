# 11 两次采集回顾：用户质疑"锁曝光会飘"，方案改成按 session 锁

会话：回顾 11-01 夜间和 11-02 白天两次采集，提出下一轮改进　日期：2026-11-03

## 提示词（整理）
> 看一下历来两次的采集，有什么可以改进的？
> （之后）曝光锁定是什么意思？那有时候会飘啊？

## 模型回答（摘要）
- 可靠性没问题：18 个 session 全部完成，无超温，串口重连 0 次，相机断流 0 次；约 4.9 万帧里无效的只有 12 帧 `cam_gap` 和 1 帧过曝。
- 白天改为各路独立游走后，9 路 ΔT 平均相关从 0.97～0.98 降到 0.64～0.86，这项改动有效。
- 最大问题：不加热时散斑也在去相关。10 s 间隔基线段约 0.80，快速升降温段 0.60～0.70，只差约 0.15。
- 自动曝光一直开着：白天曝光从 58 涨到 242，单个 session 内曝光与时间相关 0.57～0.75，等于引入一个和时间强相关的混杂量。
- 不加热对照太少，每个 session 只有 60 s 基线；std 固定台阶占 7/18；验证集固定用最早两个 session 会混进背景漂移。

## 纠错
- 模型第一版建议是"锁定曝光（ae=false，固定一个值，比如 60 左右）"。用户质疑光源会飘。
- 模型承认这个担心成立：白天光功率掉了约 4 倍，整天锁死同一个值，下午画面会暗很多。方案改为按 session 锁：session 开始前让 AE 收敛，基线开始时冻结曝光和增益，session 结束后恢复。
- 同时补了两条防护：冻结时目标亮度降到 90 左右留出余量；亮度偏离锁定值超过 ±30% 时写一条事件。并指出锁定后的亮度曲线反而能直接反映光功率的真实变化，之前被 AE 补偿掉了。
- 训练侧会话提出"每秒连续取 5 帧存中位数"的需求，模型先实测链路能否做到，再写代码。离线测试原先会改真相机的曝光设置，模型把这类调用打桩隔开。

## 结果
- 改进项全部被训练侧采纳，写进交接规范 v1.3：按 session 锁曝光、纯对照 session、长平台、std 每轮 1 个、上限放宽、验证集按时间穿插。
- `ramp_collect.py` 新增锁曝光、每秒 5 帧中位数、亮度偏离事件；4 个离线测试全部通过。
- 实机不加热试跑 90 s：曝光固定在 202，帧间隔 1.00 s，5 帧在 0.5 s 内取完，结束后 AE 恢复。
